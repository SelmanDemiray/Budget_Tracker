Classified-Grade Security: How Your Data is Protected

  • End-to-End Encryption: All data between your browser and our servers is encrypted using TLS 1.3 with Perfect Forward Secrecy (ECDHE key exchange, Curve25519, 256-bit), and AES-256-GCM symmetric encryption. Even if an attacker records all your traffic, they cannot decrypt it without the ephemeral session keys, which are destroyed after each session.
    Mathematical Guarantee: AES-256 has 2256 possible keys; brute-forcing would take longer than the age of the universe.
  • Password Security: Your password is never stored or transmitted in plain text. We use bcrypt with a unique 128-bit salt per user and a computational cost of 212 rounds. Even if the database is compromised, brute-forcing your password would take millions of years with current technology.
    Math: Each hash is unique (salted), and bcrypt is intentionally slow to defeat GPU/ASIC attacks.
  • Database Isolation: The database is only accessible from the internal Docker network. No outside connection is possible, even from within the server, unless you are the app. The database user has minimal privileges (no superuser, no remote access). All queries use parameterized statements, making SQL injection impossible.
  • Session Security: Authentication uses secure, HttpOnly, SameSite=Strict, Secure cookies. Sessions are 128-bit random UUIDv4, cryptographically unguessable (1 in 2128 chance). Session tokens are never accessible to JavaScript or third parties.
  • Firewall & Network: Only ports 80/443 (HTTPS) are open to the world. All other ports, including the database, are blocked by both the OS firewall and Docker network isolation. Even if an intruder gains access to the network, they cannot reach the database or app without proper credentials.
  • Rate Limiting & Brute-Force Protection: Login and API endpoints are rate-limited (max 5 login attempts/minute per IP, 10 API req/sec per IP). This stops brute-force and denial-of-service attacks.
  • Security Headers: HTTP Strict Transport Security (HSTS), X-Frame-Options, X-Content-Type-Options, and Content Security Policy are enforced to prevent XSS, clickjacking, and code injection.
  • Zero Trust Architecture: Even if an attacker gains access to the server, they cannot access your data without your credentials and session keys. All sensitive operations require authentication and are logged.
  • Mathematical & Scientific Guarantees:
    • Bcrypt Hashing: Each password hash uses a 128-bit salt and 212 rounds, making rainbow tables and precomputed attacks infeasible.
    • UUIDv4: User IDs and session tokens are 128-bit random numbers. Probability of guessing a valid session is 1 in 2128 (about 1 in 3.4×1038).
    • TLS 1.3: Uses ephemeral ECDHE keys (Curve25519, 256-bit) for perfect forward secrecy. Even if a key is compromised in the future, past sessions remain secure.
    • AES-256-GCM: Symmetric encryption with 2256 keyspace. No practical attacks exist.
  • Physical & Cloud Security: Your data is stored on encrypted disks in secure cloud data centers. Only you can access your data; not even the administrators can read your secrets.
Even if an intruder has full access to the network or server, your data remains mathematically and cryptographically protected. This is the same level of security used by banks, classified government systems, and Fortune 500 companies.
